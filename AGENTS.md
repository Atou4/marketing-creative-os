# Marketing Creative OS — Agent Rules

## Required operating order
1. Read `01-Brand-Brain/MASTER-CONTEXT.md`.
2. Read project context under `13-Projects/` when one exists.
3. Identify objective, audience, awareness stage, platform, format, and offer.
4. Inspect grounded inputs before generating: proof, customer language, winning creative, comments, brand assets, and recent performance.
5. Create or select angles **before** writing executions.
6. Produce a creative brief before rendering assets.
7. Run brand, claims, format, accessibility/readability, and platform QA.
8. Stage for human approval. Do not publish or spend by default.
9. After results arrive, update `11-Performance/` with learnings and confidence.

## Evidence vocabulary
- `official` — primary documentation/platform/repository.
- `measured` — experiment with usable methodology.
- `first-party` — this brand's customers, analytics, ads, comments, interviews.
- `community` — practitioner anecdote/discussion.
- `inspiration` — visual/creative reference, not evidence.
- `hypothesis` — idea requiring validation.

## Grounding rules
- Never invent claims, testimonials, customer quotes, review text, metrics, certifications, partnerships, or product capabilities.
- Every strong claim should point to `02-Product-Marketing/Proof-Bank.md` or a project-specific source.
- Every scaled creative batch should cite the source angle or input that inspired each concept.
- If grounding is insufficient, output a research/input request rather than plausible filler.

## Creative rules
- Avoid generic AI aesthetics and generic AI prose.
- Do not make every post use the same layout, hook structure, or cadence.
- Adapt content to the platform rather than cross-posting unchanged.
- Preserve recognizability with stable tokens: typography, colors, image treatment, logo rules, spacing, and voice.
- Use real product UI and real brand/customer assets when available.

## Automation rules
- Autonomous research, drafting, analysis, formatting and QA are acceptable.
- Publishing, ad spend, regulated claims, irreversible actions, and high-reputation-risk content require human approval unless the project explicitly defines a safer approved policy.
- Recurring loops need cadence, trigger, state/dedupe, self-check, stop condition, and output.
